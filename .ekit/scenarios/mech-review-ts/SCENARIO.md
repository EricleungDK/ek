# mech-review ts: a skip marker is a fail, a clean change passes with skipped checks named, a named test runs red, a Stryker MISSED fails on changed lines, a ts production change runs the mutants job

- story: As a TypeScript repo owner I run `mech-review.py` with `--stack ts` and trust it: a test I skip or `.only` to go green fails, a clean change says what it did not run, a test that passes before the fix fails red-first, a mutant the tests miss on a changed line fails with its location, and a production change makes the mutants job run.
- covers: R2 `it.skip` (fail, exit 1); clean ts change (pass, exit 0, skipped checks named); R1 red-first on a named vitest test (fail when red passes, exit 1, and pass when red fails and head passes); R3 MISSED through Stryker replayed from the real `stryker/missed` fixture (fail, exit 1, changed lines only); `plan` on a ts production change (run true, 4 shards)
- steps:
  1. Repo on base with `src/calc.ts` (`add`, `isPositive`, `mul`, `sub`) and `tests/calc.test.ts` (`describe("Calc")` with `it("adds")`). Head 1 changes `it("adds")` to `it.skip("adds")`. Run `scripts/mech-review.py r2 --stack ts --test-paths 'tests/**'`. Expect exit 1, one R2 entry: class agent-fixable, file tests/calc.test.ts, problem names `Calc > adds` as skipped; summary `fail <head1> (1 fail, 0 confirm; ran: R2; skipped: R1 R3 R4)`.
  2. From base, add a passing `it("subtracts")` and run again. Expect exit 0 and summary `pass <head2> (0 fail, 0 confirm; ran: R2; skipped: R1 R3 R4)`.
  3. Red-first: from base, a `test(red)` commit adds `describe("Calc") > it("fresh")`; the head fixes `src/calc.ts`. The vitest runner is replayed from the captured fixtures (`tests/fixtures/vitest`), by the outcome named for `fresh`. Run `red --stack ts --head-branch agent/x`. With `fresh` failing at red: exit 0, R1 pass. With `fresh` passing at red: exit 1, the entry names `Calc > fresh`.
  4. Head 3 is the real `tests/fixtures/stryker/missed/head/src/calc.ts` (add and isPositive changed). Run `mutants --stack ts` with the Stryker replay (MECH_TEST_STUB) that copies `tests/fixtures/stryker/missed/report.json` into `reports/mutation/` and prints `stdout.txt`. Expect exit 1, five R3 entries on src/calc.ts lines 2 and 6, no entry for `sub` (line 14), summary `fail <head3> (5 fail, 0 confirm; ran: R3; skipped: R1 R2 R4)`.
  5. Run `plan --stack ts --shards 4` on head 3. Expect `{"run":true,"count":4,"shards":[0,1,2,3]}`.
- expected: exit codes and summaries as above; the caller checkout is untouched (HEAD and status unchanged); nothing written into the kit repo.
